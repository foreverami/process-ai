알고리즘 1  온톨로지 기반 로컬 LLM 공정 레시피 생성
입력:작업자 발화 $u$, 대화 상태 $D=(V, A)$, 온톨로지 $\mathcal{O}$, SHACL 규칙 $\mathcal{S}$, 로컬 LLM $\mathcal{M}$
출력:레시피 초안 $R$, 검증 결과 $\mathcal{I}$, 응답 $y$, 갱신된 대화 상태 $D'$
  1. $P \leftarrow \{\, p \mid (p,\ \texttt{vd:jsonField},\ \cdot) \in \mathcal{O} \,\}$레시피 파라미터 정의 조회
  2. $\Sigma \leftarrow \fn{Schema}(P)$;  $\pi \leftarrow \fn{Prompt}(P, \mathcal{O}, A)$온톨로지로 스키마·프롬프트 생성
  3. for $k = 1$ to $2$ do
  4. $x \leftarrow \mathcal{M}(\pi, u;\ \Sigma,\ \tau = 0)$JSON 스키마 강제 디코딩
  5. if $x \models \Sigma$ then break
  6. $\pi \leftarrow \pi \,\Vert\, \fn{Feedback}(x)$형식 오류를 알려 재요청
  7. end for
  8. if $x \not\models \Sigma$ then raise 추출 실패
  9. $V_{\mathrm{new}} \leftarrow \varnothing$
  10. for all $p \in P$ such that $x_p \neq \texttt{null}$ do
  11. if $p$ is numeric then $V_{\mathrm{new}}[p] \leftarrow \fn{Normalize}(x_p, p, \mathcal{O})$알고리즘 2, 단위 오류 시 제외
  12. else if $p \in \{\mathrm{solvent}, \mathrm{substrate}\}$ then $V_{\mathrm{new}}[p] \leftarrow \fn{Link}(x_p, \mathcal{O})$SKOS 동의어로 개체 연결
  13. else $V_{\mathrm{new}}[p] \leftarrow x_p$
  14. end for
  15. $E \leftarrow \fn{LinkEntities}(u, \mathcal{O})$최장 일치, 조사 경계 인식
  16. $V_{\mathrm{new}} \leftarrow \fn{Complete}(V_{\mathrm{new}}, E, \mathcal{O})$LLM이 놓친 항목 보완
  17. $V \leftarrow V \oplus V_{\mathrm{new}}$새 값이 이전 값을 덮어씀
  18. $M \leftarrow \{\, p \in P \mid \mathrm{required}(p) \wedge p \notin V \,\}$
  19. if $M \neq \varnothing$ then
  20. return $(\varnothing,\ \varnothing,\ \fn{Ask}(V, M),\ (V, M))$필수값은 추측하지 않고 되물음
  21. end if
  22. $R \leftarrow \fn{Instantiate}(V)$선택 항목은 기본값으로 채움
  23. $G_R \leftarrow \fn{ToRDF}(R, \mathcal{O})$장비·용매·기판 개체와 연결
  24. $\mathcal{I} \leftarrow \fn{SHACL}(\mathcal{O} \cup G_R,\ \mathcal{S})$위반·경고·정보로 분류
  25. return $(R,\ \mathcal{I},\ \fn{Draft}(R, \mathcal{I}),\ (V, \varnothing))$
알고리즘 2  온톨로지 기반 단위 정규화 $\fn{Normalize}$
입력:추출값 $x_p = (v, s)$ (값 $v$, 단위 표기 $s$), 파라미터 $p$, 온톨로지 $\mathcal{O}$
출력:기준 단위로 바꾼 값 $v_c$
  1. $c \leftarrow \mathrm{unit}(p)$qudt:hasUnit
  2. if $s = \varepsilon$ then return $v$단위 생략 시 기준 단위로 해석
  3. $w \leftarrow \fn{Lookup}(s, \mathcal{O})$qudt:symbol, skos:altLabel 비교
  4. if $w = \bot \,\vee\, \mathrm{kind}(w) \neq \mathrm{kind}(c)$ then raise 단위 오류물리량 종류 불일치
  5. return $(v + o_w)\, m_w / m_c - o_c$$m$: 변환 배수, $o$: 오프셋
표. 알고리즘 기호 정의
기호의미
$u$작업자가 입력한 실험 계획 문장
$D = (V, A)$대화 상태. $V$는 지금까지 확정된 파라미터 값(기준 단위), $A$는 직전에 되물은 파라미터
$\mathcal{O}$온톨로지 지식그래프 (TBox: 개념·속성, ABox: 장비·재료·단위)
$\mathcal{S}$SHACL 검증 규칙 집합 (장비·재료 한계, 논리 조건)
$\mathcal{M}$로컬 LLM (OpenAI 호환 API로 호출)
$P$레시피 파라미터 집합. 온톨로지에서 vd:jsonField가 정의된 속성
$\Sigma,\ \pi$구조화 출력용 JSON 스키마, 추출 프롬프트. 모두 $P$의 이름·동의어·단위로 생성
$\tau$샘플링 온도
$x,\ x_p$LLM 추출 결과와 파라미터 $p$의 값. 수치 항목은 (값, 단위 표기) 쌍
$E$발화에서 찾은 온톨로지 개체 (용매, 기판, ‘최대 진공’ 같은 정성적 설정값, 공정 순서)
$\fn{Complete}$$E$로 LLM이 놓친 항목을 채움. 용매·기판은 발화에 하나만 있을 때, 정성적 설정값은 장비 구성품 속성값(예: 펌프 최저 도달 압력)으로
$V \oplus V_{\mathrm{new}}$$V_{\mathrm{new}}$에 있는 항목은 새 값으로 바꾸고, 나머지는 $V$의 값을 유지
$M$아직 값이 없는 필수 파라미터 (목표 온도, 목표 압력)
$R,\ G_R$레시피 초안과 그 RDF 그래프 표현
$\mathcal{I}$SHACL 검증 결과 (위반·경고·정보)
$m_w,\ o_w$단위 $w$의 QUDT 변환 배수와 오프셋. $\mathrm{kind}(w)$는 물리량 종류
